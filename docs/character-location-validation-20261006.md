# 单元格内错误文字定位验证

日期：2026-10-06。环境：Windows，WPS 12.1.0.28505。
开发分支：`fix/formula-bar-character-location`，基于 `8402caf`。

## 已观察的真实宿主行为

仅操作独立测试工作簿 `ui-reuse-validation.xlsx` 的 B6；不发送业务文字。

- WPS 原生校对能在公式栏显示蓝底选区，单元格内同步显示黑底选区。
- `Range.Characters` 对象没有可调用的 `Select` 方法。
- 临时将 `EditDirectlyInCell` 从 true 设为 false，通过 F2 进入公式栏，再用 Ctrl+Home、带重复次数的 Right、Shift+Right，可分别精确选中句号和逗号错误。
- 编辑状态下 `Application.Ready` 仍然返回 true，不能用它判断编辑是否结束。
- 公式栏编辑状态内恢复 `EditDirectlyInCell` 可能无效；在正常 Enter 或 Escape 退出后可以恢复 true。
- 原型的“结束定位”通过宿主 SendKeys Enter 正常退出编辑，后台恢复成功，读取原文未变。
- 隐藏任务窗格后，功能区主页面的后台检查仍在运行；手动退出编辑、重新打开窗格后，读取设置为 true、恢复标记为空。
- 编辑状态内 ActiveCell 和 Selection 的地址都为实际目标 B6，可用于拒绝向其他单元格发送延迟导航键。

正式问题卡已实测：连续点击逗号、句号、逗号卡片，公式栏蓝底和单元格黑底随卡片正确切换，无需先点击空白单元格。

定位后的正式“修正”按钮已连续实测两次：先去掉重复逗号，再去掉重复句号，B6 最终为 `第1条检查，内容。`。第一条修正后，第二条偏移重新计算，仍能准确选中句号。

两处故障与原生编辑器焦点有关：延迟定位前再次激活工作表会抢走公式栏焦点；同步发送 Enter 后卡片的禁用/重绘也会影响焦点。现在不再二次激活，并在面板完成状态更新后提交编辑，等待宿主恢复设置后才继续安全写回。

## 正式实现边界

- 主页面负责后台恢复，任务窗格负责本次字符定位会话。
- 本地持久恢复标记用于异常退出后的原设置恢复；没有可靠存储或后台心跳时，只定位单元格。
- 切换卡片、修正、撤销或重新校对前，正常提交本次目标的编辑，再重新验证身份和原值。不会用 Escape 丢弃用户输入。
- 延迟发送导航前再次验证工作簿、工作表、ActiveCell 和 Selection。身份变化时不发送按键。
- 自动转到下一条只选择单元格，不进入编辑，以保留修正后原生 Ctrl+Z 的使用方式。
- 当前只启用已验证的普通字符串偏移；换行、制表符、代理对字符、组合附加符号退回单元格定位，并提示不能精确选中。
- 以单元格内编辑设置为 true 为已验证前提；原设置为 false 或属性不可靠时退回单元格定位，不覆盖用户偏好。

## 自动测试

已补充：精确偏移、设置恢复、独立后台页面、持久恢复、延迟操作跨单元格/工作簿保护、手动编辑提交后旧建议拒绝、编辑结束等待期间工作簿切换、自动下一条不进入编辑等用例。

最近完整测试：153 项通过，0 项失败。新增覆盖面板重绘后发送 Enter，以及原生编辑结束慢于 700ms 的情形。

## 真机验收步骤

1. 重启 WPS 加载正式主页面；使用 B6 本地规则生成两条标点错误，不调用模型。
2. 点击两张问题卡，确认蓝底/黑底选区分别对应逗号与句号。
3. 定位后点击修正，确认仅目标片段改变，设置恢复为 true，下一条只定位单元格。
4. Ctrl+Z 一次，确认目标恢复；再次定位另一张卡不受影响。
5. 在公式栏手动改变目标原文，再点旧建议的修正；确认保留手动输入并拒绝旧建议。
6. 定位期间关闭面板、结束编辑并重新打开；确认设置恢复。
7. 长中文文本多处错误仍待补测；换行与特殊 Unicode 当前按上述边界降级。

正式真机结果：步骤 2、3、4 通过；步骤 6 的独立后台恢复已实测。步骤 5 的手动输入保护本轮仅自动测试，长文本步骤 7 未实测。本轮只使用本地标点规则，没有调用大模型。

Ctrl+Z 能恢复修正前内容、面板同步恢复待处理状态。不过结束公式栏编辑也可能产生一个没有文字变化的原生撤销步骤：连续撤销两次修正时，可能需要多按一次 Ctrl+Z。尝试外层原生事务合并时出现编辑结束确认超时，故未加入正式实现。这个撤销体验限制仍未解决。

临时诊断控件已移除，正式面板已重新加载；确认 `EditDirectlyInCell` 恢复为 true，恢复标记为空。没有保存测试工作簿，也没有修改文字版仓库。

## 合并单元格兼容补充

用户反馈普通单元格成功而合并单元格失败。代码检查发现：`characterTargetActive` 将 Selection 地址按单格解析；B6:C6 被解析为空，因此延迟选中文字和结束编辑均被拦截。

现仅允许 Selection 恰好等于目标单元格的 MergeArea，且目标必须是合并区域的左上角文字单元格；ActiveCell、原工作簿和原生工作表核验继续保留。合并区域改变、选区扩大或合并身份无法核实时，不向原生编辑器发送延迟按键。安全写回仍只操作原单元格地址。

新增自动测试：合并区域内精确定位与安全写回、扩大选区/改变合并结构拒绝导航、无法核实左上角时降级。完整测试 156 项通过。合并单元格真机：未实测；原测试工作簿窗口已关闭，目前打开的是业务表，未对其执行测试修改。

验收：在测试表合并 B6:C6，B6 写入 `第1条检查，，内容。。`；本地规则生成两条问题，连续点击两卡，再分别修正，检查蓝底/黑底选中文字、原值保护及 Ctrl+Z。纵向合并 B6:B7 也需验证。重新打开 WPS 后加载最新代码。
