# ET 工作表身份兼容验证（2026-10-05）

## 原因与修复

本机 WPS Office 12.1.0.28505 的实际工作表未提供有效的 `Worksheet.CodeName`，此前将此字段设为必需项，导致校对前提示“无法确认原工作簿或工作表”。重新打开文件不会补齐此字段。

CodeName 不可用时，保存原工作表的原生 A1 Range，用 `Application.Intersect` 核验当前工作簿集合中的工作表仍为原对象。不能用 JavaScript `===` 比较 WPS 宿主包装对象，也不能仅按工作表名称重新查找目标。Intersect 不可用、返回异常或核验失败均拒绝操作。

工作簿 FullName/Hwnd、工作表 Parent/Name、地址、写前原值及公式检查继续保留。身份失败现在显示具体缺失字段。

原生 Intersect 行为参考：[WPS 官方文档](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/et/Application/member/Intersect)。

## 真机步骤与结果

1. 保存并完全退出 WPS，重新打开文件，加载当前开发服务（3892）。确认原错误诊断指向 CodeName。
2. 打开独立测试文件 `.local-validation/et-v020-validation-20261005.xlsx`，在“校改测试”选中 A2:D4。A/C 为数字，D 为公式，B2/B3/B4 为测试文本。
3. 开始校对，OpenCode 实际返回 B2/B3/B4 三条问题，未出现数字或公式单元格问题。
4. 点击 B3 问题卡，真实选区定位为 B3。
5. 点击 B3“修正”，原值“疏散通到堆放杂物。”变为“疏散通道堆放杂物。”，卡片进入“已处理（1）”；其他单元格显示值保持不变。
6. 将 B2 手动改为“用户已修改，测试保留。”，再点击原 B2 建议的“修正”。显示“单元格内容已变化，请重新校对。”，新值保留，建议标为需重查。

以上步骤均已实测。启动时一次业务表格请求已取消，未对业务表格执行写回；完整闭环使用独立测试文件。

删除原表后新建同名表、切换同名不同工作簿的本轮真机负向测试未实测；由自动测试覆盖，不将其列为真机通过。当前表面板确认次数本轮未实测。
